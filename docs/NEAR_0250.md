# `0x0250` near-miss audit

This report covers the 166 functions in `0x02500000..0x02510000` that the block
sweep emitted as `DIFF`. A `DIFF` means the candidate did not reproduce the
target instructions and bytes; it is not registered in `src/functions.tsv`.

## Outcome

- Original `DIFF` rows: **166**
- Recovered and registered: **22** (19 indirect selectors plus 3 `0250E3` functions)
- Archived open near misses: **144** in [`../src/near/0250/`](../src/near/0250/README.md)
- Still-open families: **+0x78 indexed field** 58, **02508B6C cluster** 69, **other** 17

The three `0250E3` recoveries are byte-exact and already in the table. The 19
selectors reused the same shape: load the selector word, mask/shift it, and
dispatch through the indexed table. Both groups are listed below for audit.

## Root causes

### `02508B6C` cluster

This is the largest family. The corrected representative `02508D90` improves
from 15/41 to 19/41 candidate words, with the best stack order
`spC-sp8-sp10-sp14`; every tested `-O` level still differs in callee-save
selection and register scheduling. The family is therefore source-shape
correct but allocator-blocked, not a missing external declaration.

### `+0x78` indexed-field cluster

These use the pointer-array shape at object offset `0x78`. Modelling the field
as a pointer rather than an inline array removes the large address-scale
differences, but the representative `0250C568` still produces a 140-byte object
against the 144-byte target and disagrees on the `*arg1` reload and the
`sp8`/`spC` stack slots. `0250C668` is at 15/38 and `0250E62C` at 17/20; the
latter loads an inner pointer through `r11` where the target uses `r3`.

### Other

`0250FE00` uses vector instructions and has an m2c-recovery error plus a
different loop allocation. The remaining rows are isolated selector or load
shape differences, not a common family.
